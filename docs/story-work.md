# 써클(Circle) — AI 없이 손으로 했던 작업 과정 (마지막 경험)

> `docs/story-service.md`는 무엇을 위한 일인지의 기준이고, 이 문서는 실제로 어떻게 했는지의 기록이다. 두 문서는 서로 다른 기준이므로 섞지 않는다.

## 작업 순서

1. 나는 UIBowl에서 경쟁사 레퍼런스를 수집하고, 분석해 우리 서비스에 반영할 부분을 가져온다.
2. 나는 Figma에서 레퍼런스와 화면 설계서를 반영한 UI 키스크린 2~3개를 440×440 원형 사이즈로 그린다.
3. 나는 내부 관계자들과 협의한 뒤 컨셉 방향을 확정한다.
4. 나는 정해진 컨셉에 따라 서비스 화면 설계 문서를 구체화한다.
5. 나는 컨펌된 디렉션 안에서 마이너한 디자인 옵션 2~3개를 그린다.
6. 나는 디자인 디렉터와 협의해서 최종 시안을 컨펌한다.
7. 나는 디자인 토큰과 컴포넌트를 제작하고 화면 디자인에 들어간다.

## 핵심 게이트

1. **레퍼런스 반영 포인트 선정 (1단계):** 분석 결과에서 서비스에 반영할 포인트를 선택한다.
2. **컨셉 방향 확정 (3단계):** 키스크린을 바탕으로 내부 관계자와 방향을 합의한다.
3. **최종 시안 컨펌 (6단계):** 디자인 디렉터와 최종안을 확정한다.

## 주요 전달 경계

- **도구 경계:** UIBowl에서 레퍼런스를 수집한 뒤 Figma에서 키스크린을 만든다.
- **협업 경계:** 키스크린과 컨셉 방향을 내부 관계자와 협의하고, 최종 디자인 옵션은 디자인 디렉터와 협의한다.
- **산출물 흐름:** 레퍼런스·분석·반영 포인트 → 키스크린 → 확정 컨셉 → 화면 설계 문서 → 디자인 옵션 → 최종 시안 → 디자인 토큰·컴포넌트·화면 디자인.
